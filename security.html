Security

For IT and security teams · Last updated 6 November 2026

The short version

Calendar Wrapped reads calendars in the browser, on the person’s own device. The calendar is never uploaded: our servers have no endpoint that accepts one. The browser is told, through a Content Security Policy, that it may only talk to this site, and to Google or Microsoft when someone chooses to sign in with them. Anyone can check this by using the app with the network switched off.

Where calendar data goes

A calendar file (.ics)Never leaves the device
Read and analysed in the browser, in a background thread. Every chart, card, image and video is made on the device.
Google sign-inBrowser ↔ Google only
Read-only scope calendar.events.readonly. The browser fetches events straight from Google. The token is kept in memory, never stored, and revoked once the events have loaded. Our servers never see the token or the events.
Outlook sign-inBrowser ↔ Microsoft only
Read-only scopes Calendars.Read and User.Read, with the PKCE flow and no client secret. The token is kept in memory and discarded when the events have loaded.
Results on the deviceStays on the device
The summary (which includes names and meeting titles) is kept in the browser for 30 days and then cleared. With Keep results on this device switched off, it lives only in that tab and is gone when the tab closes. Start over clears it immediately.
Share linksOnly when someone shares
The link carries the numbers on the card. Names and meeting titles are left out unless the person switches them on. The server reads the numbers to draw a link-preview image and stores nothing. Request logging is off.
Emailing the planOnly when someone asks
The plan text, which includes meeting titles, is sent to our email provider to deliver it, and is not kept. This is the only feature that sends calendar-derived text.
Compare with othersOnly when someone taps it
Three rounded numbers (share of time in meetings, meetings a day, wall-to-wall days) join an anonymous pool. Nothing that identifies the person.
Usage countsEvent names such as “story finished”, counted per day. No cookies, no identifiers, no IP addresses.
Error reportsThe error’s type and shape only. Anything quoted, any name, address, email or number is removed in the browser, and again on the server, before it is logged.

How it’s enforced

  • Content Security Policy on every page. Outgoing connections are limited to this site, Google’s calendar and sign-in hosts, and Microsoft’s. A script that tried to send data anywhere else would be blocked by the browser:
default-src 'self'; script-src 'self' https://accounts.google.com; style-src 'self' 'unsafe-inline' https://accounts.google.com; img-src 'self' data: blob:; media-src 'self' blob:; font-src 'self'; connect-src 'self' https://www.googleapis.com https://oauth2.googleapis.com https://accounts.google.com https://graph.microsoft.com https://login.microsoftonline.com; frame-src https://accounts.google.com; worker-src 'self' blob:; manifest-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
  • No third parties in the page. No analytics companies, tag managers, ad networks, CDNs or hosted fonts. Every script, font and library is served from this site.
  • Libraries are vendored and pinned: ical.js (MPL-2.0) to read calendar files, mp4-muxer (MIT) for the story video, and the Bricolage Grotesque typeface (SIL OFL). There are no runtime package downloads.
  • Other headers: Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, HSTS, and a Permissions-Policy that turns off camera, microphone, location, payment and USB.
  • No accounts. There is nothing to sign up for and no profile on our side. Purchases are confirmed by Stripe and recorded on the device.

Check it yourself

  1. Open the site once, so the browser keeps a copy of the app.
  2. Switch off Wi-Fi (or use your browser’s offline mode).
  3. Drop a calendar file in. The whole story, summary, report, cards and video still work, because nothing needs the network.

Or keep the network on and watch your browser’s developer tools (Network tab) while you use it: the only requests are for the app’s own files.

For a support case, the diagnostics page makes a redacted report and an anonymised copy of a calendar, with names, emails, titles and locations replaced, on the device.

Who runs what

  • Cloudflare hosts the site and runs the small server part: payments, share-link previews, the anonymous benchmark pool and counts.
  • Stripe handles payments. We never see card details.
  • Resend sends the plan email, only when someone asks for it.
  • Grafana Cloud holds the anonymous daily counts and scrubbed error reports.

Highly sensitive and classified calendars

The design keeps calendars on the device, but Calendar Wrapped is not accredited for classified or government security-marked information. If your calendar is under a classification scheme, exporting it to a laptop is a handling decision your policy already covers, and we’d recommend not using this or any unapproved tool with it.

For confidential business calendars, the safest way to use it is:

  • switch off Keep results on this device, so nothing outlives the tab;
  • leave names and titles off share cards (the default), and don’t use the email feature;
  • if you want certainty, load the page and then go offline before adding your calendar.
